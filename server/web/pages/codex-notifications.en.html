Codex notifications on your watch

Codex can work on its own for a long while, until it needs your approval to run a command or reaches the end of its task. Agentchi forwards those moments to your Wear OS watch through Codex hooks, and sends your answer back, so you don't have to keep an eye on the terminal.

What lands on your watch

In CodexOn the watchWhat you can do
Permission request: command, file edit, MCP toolWhat Codex wants to do, with a countdownAllow or deny, with or without a reason
Task finishedThe end of the agent's last message, and Chi celebratesReply with the keyboard, by voice or with a quick reply
Sessions starting and endingThe Active sessions screenSee which sessions are running

Answering from the watch is a setting: turn on Settings › Replies › Reply from the watch when you leave your screen. The watch waits up to five minutes for your answer; after that, the request stays on the computer.

Set it up

On the watch, connect to the server and create a code (Settings › Server › New code), one per computer. Then, on your computer, register the hooks and make the code visible to Codex:

curl -fsS {{.URL}}/v1/codex-hooks.json -o ~/.codex/hooks.json
echo 'export AGENTCHI_CODE=XXXX-XXXX-XXXX' >> ~/.zshrc   # or ~/.bashrc
  • Already have a ~/.codex/hooks.json? Merge the two files instead of overwriting yours (see Agentchi's hooks).
  • Approve the hooks. Codex ignores a hook until you've approved it: run /hooks in Codex and approve Agentchi's.
  • Prefer a plugin? In the Codex desktop app, add the marketplace with codex plugin marketplace add Pelagoss/agentchi, then install agentchi-codex from the plugin directory. It reads the code from AGENTCHI_CODE and the server from AGENTCHI_SERVER.

Finish with Settings › Server › Test push on the watch: if something is wrong, the watch shows the error.

Where it works

The Codex CLI, the Codex app and the IDE extension, on macOS, Linux and Windows through WSL: they all run the same hooks from ~/.codex/hooks.json.

Current limits

  • Codex's multiple-choice questions stay on the computer: Codex doesn't pass them to hooks.
  • In Active sessions, a Codex session doesn't switch back to “working” when you write to it, because Codex hooks don't report sent messages.

Using Claude Code too? The same watch and the same server handle both: see Claude Code notifications.
