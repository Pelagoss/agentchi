Héberger ton serveur Agentchi

Par défaut, la montre et les plugins passent par agentchi.dev, déjà configuré et gratuit. Si tu préfères tout garder en main, le serveur relais est open source et tourne partout.

Ce que fait le serveur

Il reçoit les événements qu'envoient tes hooks Claude Code et Codex, et pousse chacun aussitôt vers la bonne montre par Firebase Cloud Messaging. Il ne garde pas les événements : il ne stocke que les montres enregistrées et une empreinte de leurs codes. Une question qui attend ta réponse reste dans sa mémoire cinq minutes au plus. Il est multi-utilisateur : chaque montre s'enregistre seule et ne reçoit que ses propres événements.

C'est un seul binaire Go sans dépendance, qui sert aussi la page d'accueil et ces guides, avec sa propre adresse dans chaque commande.

Ce qu'il te faut

  • Un projet Firebase (gratuit) avec une appli Android pour le package fr.codingpacer.agentchi, et une clé de compte de service pour que le serveur envoie les pushs.
  • Une version de l'appli montre liée à ce projet : les jetons de push appartiennent à un projet Firebase, l'appli montre doit donc être compilée avec les valeurs de ton projet. La CI du dépôt produit cet APK, qui s'installe avec adb.
  • Un nom de domaine qui pointe vers ton serveur, ports 80 et 443 ouverts.

Docker Compose

Caddy obtient seul le certificat HTTPS. Place ta clé de compte de service dans server/firebase-service-account.json, puis :

git clone https://github.com/Pelagoss/agentchi && cd agentchi/server
chmod 644 firebase-service-account.json    # lisible par le conteneur
CC_DOMAIN=agentchi.example.com docker compose up -d

Sans Docker

Lance go build dans server/ et démarre le binaire derrière ton reverse proxy. Laisse les requêtes POST /ask ouvertes cinq minutes : Traefik et Caddy le font par défaut.

VariableRôle
CC_FCM_CREDENTIALSChemin de la clé du compte de service, obligatoire pour les pushs
CC_ADDRAdresse d'écoute, :8080 par défaut
CC_DATAFichier d'état, data/state.json par défaut
CC_PUBLIC_URLAdresse publique affichée dans les commandes, sinon déduite de la requête
CC_TRUST_PROXYtrue derrière un reverse proxy
CC_MAX_DEVICESNombre maximal de montres, 1000 par défaut, 0 pour aucune limite
CC_INDEXABLELaisse les moteurs de recherche indexer le site. Ne la définis pas : ton instance reste accessible mais hors des résultats de recherche

Connecter la montre et tes agents

Sur la montre, Paramètres › Serveur : saisis l'adresse de ton serveur et touche Connecter la montre. Ouvre ensuite la page d'accueil de ton serveur : elle donne la commande du plugin, le bloc des sessions cloud et les hooks Codex avec son adresse. Termine par Paramètres › Serveur › Tester le push, qui affiche l'erreur sur la montre si un push ne passe pas.

Le guide complet d'auto-hébergement (en anglais) détaille les valeurs Firebase, la compilation de l'appli montre et le déploiement Kubernetes.
